# Audit: `@analogjs/vite-plugin-angular` 2.8.1

Appendix to [vite-plugin-investigation.md](vite-plugin-investigation.md). Research done on 16 October 2026 by reading source only; nothing was installed or run.

**Short answer:** the claim that Analog's plugin works around Vite rather than with it holds for its default compile path. It's incomplete in two ways. Analog already ships an opt-in per-file compiler (`fastCompile`). And some workarounds, the `node_modules` linker and template type-checking, would remain with any per-file compiler.

## What was audited

- npm `latest` is **2.8.1**, `gitHead` `58a9df609050ba9d43bcc062316a477216a03015`, the head of `main`.
- Read from a tarball of the default branch `beta` at `0e3fb39d`. A GitHub compare shows `beta` = `main` + one merge commit with no changes under `packages/vite-plugin-angular`, so the line numbers below hold at `58a9df6`.
- Also checked briefly: `alpha` at `83a6eba6` (3.0.0-alpha.94). It still defaults to `NgtscProgram`; the Compilation API becomes a separate experimental plugin, and `liveReload` defaults to `true` there (`alpha` `angular-vite-plugin.ts:224`).
- "avp" below means `packages/vite-plugin-angular/src/lib/angular-vite-plugin.ts`. All links are at `58a9df6`.

2.8.1 has three compile paths:

- **Default:** `NgtscProgram` plus a TS builder program.
- **Compilation API:** `experimental.useAngularCompilationAPI`, default `false` ([avp:195-196](https://github.com/analogjs/analog/blob/58a9df609050ba9d43bcc062316a477216a03015/packages/vite-plugin-angular/src/lib/angular-vite-plugin.ts#L195-L196)), using `@angular/build/private`.
- **`fastCompile`:** Analog's own per-file oxc plus `@angular/compiler` compiler, default `false`.

The docs say the default path "runs Angular's compiler through the Angular Compilation API" with full type checking ([angular-compilation.md:28](https://github.com/analogjs/analog/blob/58a9df609050ba9d43bcc062316a477216a03015/apps/docs-analog/src/content/guides/angular-compilation.md?plain=1#L28)). In 2.8.1 the default is `NgtscProgram` with `disableTypeChecking: true` ([avp:193](https://github.com/analogjs/analog/blob/58a9df609050ba9d43bcc062316a477216a03015/packages/vite-plugin-angular/src/lib/angular-vite-plugin.ts#L193)), which `@analogjs/platform` overrides to `false` ([platform-plugin.ts:127](https://github.com/analogjs/analog/blob/58a9df609050ba9d43bcc062316a477216a03015/packages/platform/src/lib/platform-plugin.ts#L127)).

## Analog and ngp

No mention of ngp, the hybrid preprocessor, `HybridCompiler`, `processFile` or tsgo in Analog's issues, PRs, discussions or source (`beta` and `alpha`). Analog's own direction is `fastCompile`: [COMPILER.md:371-381](https://github.com/analogjs/analog/blob/58a9df609050ba9d43bcc062316a477216a03015/packages/vite-plugin-angular/src/lib/compiler/COMPILER.md?plain=1#L371-L381) calls single-file transforms with a separate global registry "the likely direction" for Angular once TypeScript moves to tsgo. PR [#2368](https://github.com/analogjs/analog/pull/2368), which proposed `@oxc-angular/vite` as an opt-in engine for `fastCompile`, was closed without merging on 2 July 2026, with no reason given. Discussion outside GitHub wasn't checked.
